# 2026-07-28 — 앱 내 업데이트 알림

## 요구사항

- 10분에 한 번 GitHub 릴리즈 확인
- 앱 버전보다 높은 릴리즈가 있으면 상단에 업데이트 버튼 (다운로드 아이콘 +
  라벨 + X 닫기 pill)
- 앱 버전을 릴리즈 태그 버전과 동일하게 유지
- v0.3.1에 포함

## 구현

### services/update_checker.dart (신규)

- `const appVersion = '0.3.1'` — 릴리즈 태그의 숫자 부분과 같아야 한다.
  pubspec.yaml과의 drift는 테스트가 잡는다.
- `parseVersion` / `isNewerVersion`: `v0.3.2` → [0,3,2] 파싱 후 자리별 숫자
  비교. 문자열 비교였다면 틀렸을 `0.3.10 > 0.3.9`도 정확. 자리수가 다르면
  없는 자리를 0으로 본다. **파싱 불가는 false** — 알 수 없는 태그 형식으로
  배너를 잘못 띄우지 않는다.
- `latestReleaseFrom`: 릴리즈 목록 JSON에서 draft를 건너뛴 첫 항목.
  **`/releases/latest`를 쓸 수 없다** — 이 저장소의 릴리즈는 전부
  prerelease라 해당 엔드포인트가 404를 낸다 (gh api로 확인). 그래서
  `/releases?per_page=5`에서 직접 최신을 고른다.
- `UpdateChecker extends ChangeNotifier`: `start()`가 즉시 1회 + 10분 주기
  확인. 저장소가 public이라 **인증 없이** 조회한다 (미인증 60회/시간 한도,
  10분 주기면 6회/시간). 실패(오프라인/rate limit/파싱)는 조용히 넘기고 다음
  주기 재시도 — 부가 기능이 앱 동작을 방해하면 안 된다.
- `dismiss()`: 닫은 태그를 기억해 같은 버전은 다시 안 띄우고, 더 높은 버전이
  나오면 다시 띄운다. 앱 재시작 시 초기화 (설정 파일까지 쓸 상태는 아니다).

### widgets/update_button.dart (신규)

요청 이미지와 같은 형태의 pill: 다운로드 아이콘 + `업데이트 v0.3.2` + X.
본문 클릭 → 릴리즈 페이지, X → 해당 버전 숨김. 타이틀바 우측(테마 토글
왼쪽)에 배치.

**"Restart to Update"가 아니라 "업데이트"인 이유**: 앱이 자동 다운로드·설치·
재시작까지 하려면 Sparkle류 업데이터가 필요한데, 서명·공증 없는 DMG 배포라
그 경로가 성립하지 않는다. 라벨이 실제 동작(릴리즈 페이지 열기)과 어긋나지
않도록 맞췄다. 자동 설치는 코드 서명이 붙는 시점의 별도 작업.

### 버전 정책

`pubspec.yaml`의 semver와 `appVersion`, 릴리즈 태그를 항상 일치시킨다
(빌드 번호 `+N`만 별개). 어긋나면 테스트 실패.

## 검증

- flutter analyze clean, flutter test 481개 통과
- 신규 테스트: 버전 비교(자리별/자리수 차이/파싱 불가), 릴리즈 목록 파싱
  (draft 건너뜀/빈 목록), checker 동작(감지·중복 알림 없음·같은 버전 무시·
  dismiss 후 상위 버전 재등장·403/오프라인 무시), pubspec↔appVersion 일치,
  pill 위젯 렌더/콜백
- **실기**: `appVersion`을 임시로 0.0.1로 낮춰 debug 빌드 실행 → 타이틀바에
  `⬇ 업데이트 v0.3.1 ✕` 표시 확인 (스크린샷). 이후 원복.
