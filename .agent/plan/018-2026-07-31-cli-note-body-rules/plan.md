# CLI 노트 본문 작성 규칙 상시 노출

## 요구사항 (confirmed)

- CLI로 노트/메모를 작성할 때 항상 템플릿(서식 규칙)이 제공되어야 한다.
- 서식 규칙: 헤더 필수, `- ` 리스트, `백틱` 강조, 코드블록, 정돈된 내용은 표.
- 규칙은 help(guide)에 담는다.

## 검토한 대안: 모든 명령에 --help 선행 강제 (2회 호출 게이트)

채택하지 않음. 근거:

- CLI는 상태가 없어 "help를 이미 봤는지" 추적하려면 상태 파일이 필요하고,
  agent 세션 경계와 파일 TTL이 어긋나 오동작 여지가 크다.
- 모든 호출이 2배가 되는 비용이 영구적인데, agent는 우회 패턴(확인 플래그)을
  즉시 학습하므로 강제 효과는 첫 세션 이후 사라진다.
- 스킬 모델의 실제 구조는 차단이 아니라 "요약 상시 노출 + 전문은 필요 시
  로드"다. CLI 등가물은 명령 출력에 규칙을 동봉하는 것.

채택한 절반: "호출하면 help가 함께 뜬다"는 방향은 유지하되, 차단 없이
쓰기 명령(note new)의 출력에 규칙 요약을 동봉한다. 추가 호출 0회로 규칙
노출을 보장한다.

## 변경 범위

1. `cli/guides/note-format.md` + 데스크톱 `agent_harness.dart` `_noteFormatMd`
   (동일 유지 계약): "본문 작성 규칙" 섹션 + 템플릿 예시 추가
2. `cli/note.go` cmdNoteNew: 스캐폴드 직후 규칙 요약 stdout 출력
   (마지막 줄 = 파일 경로 계약 유지)
3. `cli/main.go` usage: note new 설명에 규칙 출력 명시

## 알려진 한계

- 기존 노트 스토어의 `.agents/note-format.md`는 하네스가 create-only라 자동
  갱신되지 않고, `guide` 명령은 클론 쪽을 우선한다. 실제 작성 순간은 note new
  출력이 커버하므로 수용. 스토어 쪽 갱신은 소유자가 결정한다.
- 스캐폴드 파일 본문에 보일러플레이트를 심지 않는다 — agent가 지우지 않으면
  앱에 잔여 텍스트가 노출되므로, 규칙은 출력으로 전달한다.
