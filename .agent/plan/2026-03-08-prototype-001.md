# SimSync Development Context

## 1. Project Identity
- **Product name**: SimSync (Simple Sync)
- **Product type**: Personal markdown-based note and work log application
- **Core value**: Date-oriented note taking + near-real-time multi-device sync + periodic AI summaries
- **Target style**: Minimal, focused, Obsidian-like UX

## 2. Product Summary
Cross-platform personal note application for mobile and desktop.
Calendar-based daily note entry, markdown authoring, date/tag search, automatic sync across devices, and AI-powered weekly/monthly/yearly summaries.

Not a team collaboration product. Closer to a personal work log / daily note system.

## 3. Target Platforms
- Mobile application (Android, iOS)
- Desktop application (macOS, Windows, Linux)

Not currently required: web app, team collaboration, shared workspaces.

## 4. Core Product Goals
1. Calendar-oriented interface for daily note creation and management
2. Markdown-first writing with rendered output
3. Automatic cross-device sync (target latency ≤ 3 seconds)
4. Periodic AI summarization of work logs
5. Simple, low-friction, document-centric UX

## 5. Domain Interpretation Rules

### "File" semantics
"File" means a user-visible note/document unit. Database-backed storage is acceptable as long as UX feels file-like.

### Calendar semantics
Calendar is a navigation surface for date-based notes. Not full event scheduling, reminders, or external calendar integration.

### Default daily note rule
First note creation per date → one mandatory default daily note. Additional notes for the same date are allowed after that.

## 6. Functional Requirements

### 6.1 Calendar-based daily note creation
- First record per date creates one default daily note
- Additional notes allowed per date
- Each note stores: `created_at`, `updated_at`
- Markdown input with rendered/readable output
- Markdown-first experience preserved

### 6.2 Search
- Date-based search
- Tag-based search

### 6.3 Automatic multi-device synchronization
- Automatic sync on create/update/delete
- Target latency: ≤ 3 seconds
- Record source device for each action

### 6.4 AI-based periodic summaries
- Weekly / monthly / yearly summaries via AI API
- Explicit user consent required before sending content to AI
- Summaries stored separately from raw notes
- Summaries retrievable later

### 6.5 Authentication
- Account-based access
- Per-user data isolation (notes, tags, sync history, summaries)

## 7. Non-Functional Requirements

### 7.1 UX/Design
- Simple, minimal cognitive load
- Obsidian-like visual/interaction feel
- Fast note entry and navigation

### 7.2 Performance
- Sync latency ≤ 3 seconds
- Immediate note loading and date navigation
- Responsive search

### 7.3 Consistency and traceability
- Preserve note metadata and device-origin information
- Support future history/version features

### 7.4 Extensibility (future, not MVP)
- Note history / revision browsing
- Export/import
- Offline editing + delayed sync
- Richer AI workflows
- Theming / dark mode
