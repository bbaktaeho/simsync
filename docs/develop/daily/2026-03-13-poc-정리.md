## PoC 진행 요약

### 1. 초기 제품/아키텍처 정의

- 2026-03-08 기준 문서에서 SimSync를 마크다운 기반 개인 노트 앱으로 정의했다.
- 핵심 요구는 캘린더 기반 일일 노트, markdown-first 편집, 멀티 디바이스 동기화, AI 주기 요약이었다.
- 초기 아키텍처는 `Flutter client + Go backend + PostgreSQL + WebSocket + AI provider` 구성이었다.

### 2. 첫 구현과 리셋

- 같은 날 로컬 파일 기반 `notecore`, Wails desktop, Flutter mobile 프로토타입까지 한 차례 구현했다.
- 2026-03-09에 해당 구현을 유지하지 않기로 결정하고 저장소를 docs 중심 상태로 리셋했다.
- 이 과정에서 클라이언트 기술 스택은 데스크톱과 모바일을 모두 포함하는 `Flutter` 단일 코드베이스로 다시 확정했다.

### 3. Flutter desktop 중심 문서 작성 UX PoC

- 리셋 이후 `desktop/` Flutter 프로젝트를 기준으로 로그인 화면, 캘린더, 노트 목록, markdown editor/preview, weekly view, theme 시스템을 구현했다.
- 로컬 파일 저장 기반 `NoteService`로 문서 작성 흐름을 먼저 검증했다.
- 이 단계의 핵심은 "일일 노트를 빠르게 작성하고 탐색하는 UX가 Flutter에서 성립하는가"를 보는 것이었다.

### 4. GitHub OAuth 로그인 PoC

- 2026-03-10에는 현재 단계를 MVP가 아니라 desktop login 중심 PoC로 다시 명확히 정의했다.
- `Authorization Code + PKCE + loopback redirect` 방식의 GitHub OAuth를 `desktop/lib/auth/` 아래에 분리된 구조로 구현했다.
- `AuthProvider`, `AuthService`, `SessionStore`, `SessionPolicy`를 나누어 이후 다른 로그인 방식을 붙일 수 있는 형태를 만들었다.
- 세션은 로컬 JSON 파일로 유지하고, `issuedAt + 24h` 기준 absolute expiry를 적용했다.

### 5. GitHub repo 기반 저장/동기화 PoC

- 초기 설계의 `Go backend + PostgreSQL + WebSocket + JWT`는 PoC 범위에서 제거했다.
- 대신 GitHub repo를 노트 저장소이자 동기화 백엔드로 사용하는 방향으로 단순화했다.
- `NoteStorage`, `SyncEngine`, `ConflictResolver` 인터페이스를 정의하고, GitHub Contents API 기반 구현을 추가했다.
- 로그인 후에는 `RepoSelectionScreen`에서 저장소를 생성하거나 연결한 뒤 에디터로 진입하는 흐름을 만들었다.
- 커밋 SHA 폴링 기반 동기화, rate limit 대응 backoff, note cache, path index까지 포함해 PoC 수준의 실제 동작을 검증했다.

### 6. PoC 마무리 개선

- 이후 계획과 현재 `main` 기준 코드에는 markdown code highlighting, heading spacing 개선, dirty flag 기반 sync 보호, note 삭제, local-only note 지원이 반영되어 있다.
- `desktop/lib/models/note.dart`에는 `StorageType`과 `isDirty`가 추가되었고, `desktop/lib/storage/local/local_note_storage.dart`로 로컬 전용 저장소가 분리되었다.
- `desktop/lib/screens/document_screen.dart`는 remote storage와 local storage를 함께 다룰 수 있도록 확장되었다.

## 추가 이슈 수정

### GitHub 세션 만료 자동 로그아웃

- 사용 중 GitHub 토큰이 무효가 되어도 앱이 즉시 로그인 화면으로 돌아가지 않는 이슈를 확인했다.
- 기존 구조는 로컬 `expiresAt`만 기준으로 세션을 복원하고 유지했기 때문에, GitHub 측에서 실제로 유효하지 않은 토큰 상태를 런타임 중에 감지하지 못했다.

### 적용한 수정

- 저장된 세션 복원 시 `expiresAt` 검사 외에 GitHub 사용자 검증 요청을 추가했다.
- GitHub 응답이 `401` 또는 `403`이면 세션을 무효로 판단하고 로컬 세션을 삭제한 뒤 비로그인 상태로 전환하도록 수정했다.
- 앱 로그인 후에는 백그라운드 세션 모니터를 두고 주기적으로 세션 유효성을 검사하도록 변경했다.
- 백그라운드 검사에서 세션이 무효로 판단되면 자동 로그아웃 후 `LoginScreen`으로 리다이렉트되도록 정리했다.
- 일시적인 네트워크 오류나 서버 오류는 토큰 만료로 단정하지 않고, 세션을 유지하도록 처리했다.

### 검증

- 관련 auth/unit/widget test를 추가해 세션 무효 복원 실패, 백그라운드 자동 로그아웃, 로그인 화면 복귀 동작을 확인했다.
- `flutter test test/auth/auth_service_test.dart test/auth/github_oauth_provider_test.dart test/widget_test.dart` 통과
- `flutter build macos` 성공

### GitHub 저장 구조 분석

- synced note는 로컬 git clone이나 별도 mirror 디렉토리에 저장되지 않는다.
- GitHub note는 `GitHub Contents API`로 직접 읽고 쓰며, note 내용과 SHA는 런타임 메모리 cache에만 유지된다.
- 로컬에 남는 GitHub 관련 데이터는 저장소 연결 정보 `~/.simsync/repos.json`, OAuth session 파일, 그리고 사용자가 지정한 `local_note_path` 설정값이다.
- 실제 markdown 파일이 디스크에 저장되는 것은 local note 경로뿐이며, 기본값은 `$HOME/Documents/SimSync`다.
