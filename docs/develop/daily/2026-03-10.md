# 2026-03-10 개발 일지

## PoC 방향 정리

- 현재 단계는 MVP가 아니라 desktop login 중심의 PoC로 본다는 점을 다시 확인
- 운영 전환은 보류하고, 우선 실제 GitHub 로그인 동작과 로컬 세션 유지까지 desktop app에서 검증하는 방향으로 정리
- 로그인 방식이 추가될 수 있다는 전제를 두고 `dependency injection` 기반 구조와 `SOLID` 원칙을 적용하기로 결정

## 인증 설계 문서화

### 작성한 문서
- `docs/plan/2026-03-10-desktop-github-oauth-design.md`
- `docs/plan/2026-03-10-desktop-github-oauth-plan.md`

### 핵심 설계 결정
- 인증 플로우는 `Authorization Code + PKCE + loopback redirect` 사용
- GitHub 로그인은 시스템 브라우저로 이동한 뒤 `127.0.0.1` loopback callback으로 앱에 복귀
- 세션은 로컬 JSON 파일로 저장
- 세션 만료는 `absolute expiry`만 두고 기본값은 24시간으로 설정
- `AuthProvider`, `AuthService`, `SessionStore`, `SessionPolicy`를 분리해 향후 다른 로그인 방식 추가에 대비

## 추가 논의 메모

### 사진 파일 기록하기

확정된 방향:
- 사진은 외부 attachment URL에 의존하지 않고 `GitHub repo` 안에 직접 저장
- 노트 본문에는 저장된 이미지 파일을 `relative path`로 참조하는 Markdown image link를 삽입
- 기본 동작은 업로드 전 `자동 리사이즈/압축`
- 에디터에서 이미지 `drag & drop` 시 drop된 caret 위치에 Markdown image link를 삽입

예상 저장 구조:

```text
notes/
└── 2026-03/
    └── 10/
        ├── daily.md
        └── _assets/
            └── <generated-name>.jpg
```

예상 본문 삽입 형식:

```md
![image](./_assets/<generated-name>.jpg)
```

논의 중 확인한 점:
- GitHub에서 자주 보이는 이미지 URL 첨부 방식은 주로 `issue / PR / comment` 첨부 흐름에 가깝고, repo 기반 Markdown은 이미지 파일을 저장소에 두고 상대 경로로 참조 가능
- 저장소 비대화를 막기 위해 기록용 품질 기준의 리사이즈/압축 정책이 사실상 필요

### AI 연동 논의

확정된 요구:
- 사용자가 선호하는 인증 방향은 `API key` 직접 입력이 아니라 `Claude`, `ChatGPT` 같은 AI tool 계정 기반 로그인
- 1차 목표 기능은 다음 두 가지
  - 주간/월간 요약 생성 후 별도 저장 및 조회
  - 사용자가 요청하면 일정 초안 등을 노트에 자동 작성

현재 판단:
- 공식 문서 기준으로는 제3자 앱이 사용자의 `ChatGPT Plus`나 `Claude Pro` 구독을 일반 API처럼 직접 소비하는 공개된 범용 방식은 불명확
- 공식 AI tool 내부의 account login과, 독립 앱이 그 구독을 재사용하는 문제는 별도로 봐야 함
- 따라서 `AI 기능 요구`와 `실제 인증/실행 수단`은 분리해서 설계하는 것이 맞음

보류 결정:
- `AI provider / login / execution path`는 아직 논의가 더 필요하므로 이번에는 확정하지 않음
- 이후 재논의 시 `SummaryEngine`, `DraftAssistEngine`처럼 기능 인터페이스와 실행 백엔드를 분리하는 방향을 우선 검토

## GitHub 기반 노트 동기화 설계 및 구현

### 아키텍처 전환 결정

기존 설계(Go 백엔드 + PostgreSQL + WebSocket)를 PoC 단계에서 대폭 단순화:
- **제거**: Go 백엔드, PostgreSQL, WebSocket 실시간 푸시, JWT 인증
- **도입**: GitHub REST API (Contents API)를 노트 저장소 + 동기화 백엔드로 사용
- Git history가 NoteRevision, SyncEvent 등의 엔티티를 대체

핵심 결정:
- 인증: GitHub OAuth (별도 개발 중인 것 활용)
- 저장 구조: `notes/{YYYY-MM}/{DD}/{title}.md`
- 동기화: 3~5초 인터벌 커밋 SHA 폴링
- 충돌 처리: Last-Write-Wins (409 시 최신 SHA로 덮어쓰기)
- 추후 다른 저장소(local, S3 등) 교체 가능하도록 인터페이스 기반 설계

### 설계 문서
- `docs/plan/2026-03-10-github-sync-design.md` — 아키텍처, 인터페이스, GitHub 구현 상세
- `docs/plan/2026-03-10-github-sync-plan.md` — 7단계 구현 계획 (TDD 기반)

### 구현된 스토리지 레이어

**인터페이스 (저장소 교체 가능)**
- `NoteStorage` — 노트 CRUD 추상화 (`listNotes`, `listDates`, `getNote`, `saveNote`, `deleteNote`)
- `SyncEngine` — 동기화 엔진 추상화 (`start`, `stop`, `syncNow`, `statusStream`)
- `ConflictResolver` — 충돌 해결 전략 추상화 + `LastWriteWinsResolver` 구현

**GitHub 구현체**
- `GitHubApiClient` — Contents API 래퍼 (파일 CRUD, Base64 인코딩/디코딩, 예외 클래스)
- `GitHubNoteStorage` — NoteStorage의 GitHub 구현 (SHA 캐시, 노트 캐시, ID→Path 인덱스)
- `GitHubSyncEngine` — 커밋 SHA 폴링 기반 동기화 (exponential backoff, rate limit 감지)
- `GitHubStorageConfig` — `~/.simsync/github_config.json` 설정 관리

**기존 코드 리팩터링**
- `NoteService`가 `NoteStorage` 인터페이스를 구현하도록 변경
- `DocumentScreen`이 `NoteStorage` 인터페이스에 의존하도록 수정
- `main.dart`에서 `StorageBundle` + `StorageFactory` 패턴으로 GitHub/로컬 스토리지 전환

### 코드 리뷰 후 수정 사항
- `GitHubApiClient`, `GitHubSyncEngine`의 `token` 등 필드를 private으로 변경 (보안)
- API 에러 시 exponential backoff 추가 (최대 5분, `X-RateLimit-Remaining` 헤더 파싱)
- N+1 API 호출 방지를 위한 노트 캐시 + ID→Path 인덱스 추가
- 타이틀 변경 시 기존 파일 자동 삭제 (고아 파일 방지)
- `SyncEngine.onRemoteChanged` → `ValueNotifier`로 DocumentScreen에 새로고침 연결
- 설정 파일 손상 시 로컬 스토리지로 자동 폴백 (이미 구현되어 있음 확인)

## GitHub Repo 선택 화면 설계 및 구현

### 설계 문서
- `docs/plan/2026-03-10-repo-selection-design.md`
- `docs/plan/2026-03-10-repo-selection-plan.md`

### 앱 흐름 변경

기존: 로그인 → 에디터
변경: 로그인 → **저장소 선택** → 에디터

- `_AuthStatus`에 `repoSelection` 상태 추가
- 세션 복원 시 `RepoCache`에 기존 연동 이력이 있으면 바로 에디터, 없으면 저장소 선택으로 이동

### OAuth scope 변경

- `read:user user:email` → `read:user user:email repo`
- `repo` 스코프 추가로 GitHub 저장소 API 접근 가능
- 기존 세션은 재로그인 필요 (스코프 변경 반영)

### 구현: RepoCache

- `desktop/lib/storage/github/repo_cache.dart`
- 연동 이력을 `~/.simsync/repos.json`에 로컬 캐싱
- `RepoEntry`: owner, repo, branch, connectedAt
- `load()`, `add()`, `remove()` 지원
- `RepoCache.withPath()` — 테스트용 경로 지정

### 구현: GitHubApiClient 확장

- `createRepo({required String name})` — private repo 자동 생성 (auto_init: true)
- `repoExists({required String owner, required String repo})` — 저장소 존재 여부 확인

### 구현: RepoSelectionScreen

- `desktop/lib/screens/repo_selection_screen.dart`
- 상단에 GitHub 아바타 + 사용자 이름 표시
- 캐싱된 저장소 목록 (바로 연동 가능)
- 새 저장소 만들기 (이름 입력 → `createRepo` → 자동 연동)
- 기존 저장소 연결 (owner/repo 입력 → `repoExists` 확인 → 연동)
- 연동 해제 (캐시에서 제거, GitHub에서 저장소 삭제는 하지 않음)
- 에러 처리: 422 (이미 존재), 404 (없는 저장소), 네트워크 오류 — 한국어 메시지

### 구현: GitHubStorageConfig → RepoCache 전환

- `GitHubStorageConfig` (`~/.simsync/github_config.json`) 삭제
- `RepoCache`가 저장소 설정을 대체
- `_defaultStorageFactory`가 owner/repo/branch를 직접 받도록 변경
- `StorageFactory` typedef에 owner/repo/branch 파라미터 추가

### 구현: GitHub 프로필 아바타

## 버그 수정 및 개선 (3-11)

### 노트 저장 후 사라지는 버그 수정

**원인**: `_loadNotes()`가 `_noteService.loadAllNotes()` (로컬 파일시스템)에서 읽는 반면, `_onNoteChanged()`는 `_storage.saveNote()` (GitHub)에 저장 — 읽기/쓰기 경로 불일치

**수정**:
- `_loadNotes()` → `_storage.listDates()` + `_storage.listNotes()`로 변경
- `_createNote()` → `_storage.saveNote()`로 변경
- 이전 월 노트도 로드 (월 초 7일 이내일 때)

### 저장 debounce 추가

- 키 입력마다 즉시 GitHub 저장 → 커밋 폭주 발생
- 타이핑 멈춘 후 **2초 뒤에 저장**하도록 `Timer` 기반 debounce 추가
- `dispose()`에서 타이머 정리

### RepoCache DI (테스트 격리)

- `SimSyncApp`에 `repoCache` 파라미터 추가 (optional)
- `_AppShell`이 주입받은 `RepoCache` 사용
- 테스트에서 실제 `~/.simsync/repos.json` 의존하던 문제 해결
- `RepoCache.withPath('/tmp/...')` 사용으로 테스트 격리
